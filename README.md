# Solina Inbox

תיבת וואטסאפ פנימית לצוות המכירות והתמיכה של סולינה — לוח בקרה משותף לניהול שיחות וואטסאפ, עם ספק וואטסאפ מדומה (mock) שמוכן להתחלף בהמשך בחיבור אמיתי ל-Meta WhatsApp Cloud API / Telnyx.

## טכנולוגיות

Next.js 16 (App Router) · TypeScript · PostgreSQL (Supabase) + Prisma ORM · Tailwind CSS + shadcn/ui · Supabase Realtime · NextAuth v5 (Credentials) · Vitest.

## הרצה מקומית

### 1. יצירת פרויקט Supabase

1. היכנס ל-[supabase.com](https://supabase.com) → New Project.
2. לאחר היצירה, עבור ל-**Project Settings → API** והעתק את `Project URL`, `anon public key` ו-`service_role key`.
3. עבור ל-**Project Settings → Database → Connection string**, ובחר בטאב **Transaction pooler**. העתק את מחרוזת החיבור המלאה (היא מכילה את שם ה-host הנכון עם ה-region של הפרויקט שלך).

### 2. התקנה

```bash
npm install
cp .env.example .env
```

מלא ב-`.env`:

- `DATABASE_URL` — מחרוזת ה-Transaction pooler שהעתקת (port 6543), עם `?pgbouncer=true` בסוף.
- `DIRECT_URL` — אותה מחרוזת בדיוק אך עם port 5432 (או ה-Session pooler / Direct connection דרך אותו host), משמש רק ל-migrations.
- `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` — מ-Settings → API.
- `NEXTAUTH_SECRET` — הרץ `openssl rand -base64 32`.
- `CRON_SECRET` — מחרוזת אקראית כלשהי.

> אם אתה נתקל בבעיית timeout/SSL בחיבור למסד הנתונים (קורה ברשתות מסוימות), נסה להוסיף `&sslmode=disable` לסוף `DATABASE_URL`/`DIRECT_URL` — אך זאת רק לצורך פיתוח מקומי, **לא** בסביבת production.

### 3. סכמה ונתוני דמו

```bash
npx prisma db push      # יוצר את כל הטבלאות ב-Supabase
npm run prisma:seed     # מאכלס 7 משתמשים, 150 אנשי קשר, 80 שיחות, תבניות ועוד
```

סקריפט ה-seed הוא אידמפוטנטי — אפשר להריץ אותו שוב בבטחה אם הוא נקטע (למשל בגלל רשת לא יציבה); הוא ימשיך מהנקודה שבה עצר.

### 4. הרצה

```bash
npm run dev
```

גלוש ל-[http://localhost:3000](http://localhost:3000) — תועבר אוטומטית ל-`/login`.

**משתמשי דמו** (כל המשתמשים חולקים את אותה סיסמה — **לפיתוח בלבד**, אין להשתמש בזה ב-production):

| תפקיד | אימייל | סיסמה |
|---|---|---|
| מנהל מערכת | admin@solina.test | Password123! |
| מנהל צוות | manager@solina.test | Password123! |
| נציג | agent1@solina.test ... agent5@solina.test | Password123! |

### 5. בדיקת שליחת הודעות בזמן אמת

היכנס כ-Admin או Manager → **הגדרות → סימולטור וואטסאפ (Demo)** → בחר איש קשר → שלח הודעה נכנסת מדומה. פתח את תיבת ההודעות בכרטיסייה נוספת (או התחבר כנציג אחר) — ההודעה תופיע שם מיידית דרך Supabase Realtime, ללא רענון.

## Docker (אופציונלי)

ברירת המחדל היא Supabase מנוהל, אבל אם ברצונך Postgres מקומי:

```bash
docker compose -f docker/docker-compose.yml --profile local-db up postgres
# עדכן DATABASE_URL/DIRECT_URL ב-.env ל-postgresql://solina:solina@localhost:5432/solinainbox
```

להרצת כל האפליקציה בתוך קונטיינר:

```bash
docker compose -f docker/docker-compose.yml --profile full up
```

## פריסה ל-Vercel

הפרויקט כולל `vercel.json` עם Cron Job (כל 2 דקות) לעיבוד אוטומציות מתעכבות (`NO_REPLY_TIMEOUT`) — דורש תוכנית Vercel Pro ומעלה. יש להגדיר את כל משתני הסביבה מ-`.env.example` כ-Environment Variables בפרויקט ב-Vercel.

## קמפיינים ורשימות תפוצה

מנהלים יכולים לפתוח **קמפיינים ורשימות תפוצה** (`/campaigns`) כדי:

- ליצור ולערוך רשימות מאנשי קשר קיימים או לייבא CSV (עד 5,000 שורות / 1MB).
- ליצור טיוטה מתבנית מאושרת עם משתנים ממוספרים; `{name}` בערך משתנה מוחלף בשם הנמען.
- להתחיל שליחה, לתזמן לפי השעה המקומית בדפדפן, להשהות, להמשיך או לבטל.
- לראות מצב לכל נמען, כולל שגיאות וסטטוס מסירה/קריאה שמגיע מ־Meta.

הייבוא מקבל עמודות `name,phone,consentStatus` (שם וטלפון חובה). ללא הסכמה מפורשת
הסטטוס הוא `UNKNOWN`. הייבוא אינו מעדכן פרטים או הסכמה של אנשי קשר קיימים ואינו
מחזיר מנויים שהוסרו. מספרי טלפון מנורמלים וכפילויות מסוננות. דוגמה:

```csv
name,phone,consentStatus
ישראל,0501234567,OPTED_IN
```

נמעני קמפיין נשמרים בעת יצירת הטיוטה, כך שעריכת רשימה אינה משנה שליחה שתוכננה.
רק אנשי קשר בסטטוס `OPTED_IN` נשלחים, עם בדיקה חוזרת בזמן השליחה. הודעה נכנסת
של `הסר`, `הסרה`, `הסר אותי`, `STOP` או `UNSUBSCRIBE` מסמנת הסרה לפני אוטומציות.

התור נשמר במסד הנתונים. `/api/cron/process-campaigns` מעבד עד 20 נמענים בכל הפעלה,
כל דקה ב־Vercel, עם נעילה אטומית לכל נמען. נדרשים `CRON_SECRET` ותוכנית התומכת
בתדירות זו. ניתן לקרוא לנתיב גם מתזמן חיצוני עם `Authorization: Bearer <CRON_SECRET>`.
עצירה אינה מבטלת הודעה שכבר התחילה להישלח. ניתוק בזמן שליחה מסומן כ״דורש בדיקה״,
ולא נשלח שוב אוטומטית; אין הבטחת exactly-once מול ספק חיצוני ללא idempotency.
הפעלות שנתקעו מסומנות לבדיקה אחרי 10 דקות. סטטוס ״הסתיים״ מציין שהעיבוד הסתיים,
ואינו אומר שכל הנמענים קיבלו את ההודעה — יש לעיין במונים ובפירוט.

**שדרוג התקנה קיימת:** יש להחיל את שינוי הסכמה המתועד ב־[prisma/changes/README.md](prisma/changes/README.md)
לפני פריסת הקוד. אין להריץ seed בייצור לצורך השדרוג.

## חיבור WhatsApp אמיתי

קיים מימוש Meta WhatsApp Cloud API ב־`src/server/providers/meta-whatsapp-provider.ts`.
בהגדרות → חיבור וואטסאפ, הזן Access Token, Phone Number ID, Webhook Verify Token
ו־App Secret (חובה לאימות חתימות). רשום את כתובת ה־webhook המוצגת במסך ב־Meta.
ללא ספק פעיל המערכת משתמשת בספק מדומה; מסך הקמפיינים מציג זאת במפורש.

יש לוודא ששמות התבניות והשפה במסד תואמים לתבניות שאושרו בחשבון Meta האמיתי.
תבניות ה־seed הן לצורכי הדגמה בלבד. הגדר WhatsApp Business Account ID והשתמש בכפתור סנכרון התבניות במסך התבניות. שליחה אמיתית מוגבלת לתבניות שסונכרנו מהחשבון המחובר. נתמכים גוף טקסט, משתנים ממוספרים וכותרת תחתונה; תבניות עם רכיבים אחרים מסומנות כלא זמינות לשליחה. יצירה והגשת תבניות עדיין לא מומשו.
בצ׳אט ניתן לשלוח תבנית מאושרת גם אחרי חלון המענה של 24 שעות; חלון ההודעות החופשיות
נאכף גם בשכבת השירות, כולל שליחות של אוטומציות. שגיאת ספק מוחזרת ככישלון ולא כהצלחה.
Webhook ללא חתימה תקינה נדחה. אירועי מסירה מאוחרים אינם מחזירים הודעה שנקראה למצב מוקדם יותר.

## פישוטי היקף מכוונים

- קיצורי מקלדת: מענה/חיפוש/סגירה בלבד.
- ייבוא CSV: מיפוי עמודות קבוע, ללא זיהוי חכם. המסך לבחירה ידנית מציג עד 1,000 אנשי קשר; API רשימות עד 10,000.
- דיוק "אין מענה תוך X דקות" תלוי בתדירות ה-cron (כל 1-5 דקות), לא מדויק לשנייה.
- אין Redis/Upstash — תור המשימות מבוסס טבלת `AutomationRun` + polling.
- @mentions בהערות פנימיות — הדגשה חזותית בלבד, ללא נוטיפיקציה.
- מדיה בספק המדומה — קישורים לדוגמה קבועים, לא אחסון אמיתי.

## מגבלות שנותרו

- קליטת הודעות נכנסות כוללת מניעת כפילויות בטרנזקציה ונעילה לפי איש קשר. אוטומציות לאחר שמירת ההודעה עדיין אינן מגובות בתור outbox עמיד לכשלי תהליך.
- נוספו קבלת ושליחת מדיה ב־Meta והצגה בצ׳אט, אך טרם בוצעה בדיקה מול חשבון Meta חי. העלאה מוגבלת ל־4MB והורדה ל־20MB. אין עדיין ארכיון קבצים לטווח ארוך או הקלטה בדפדפן; בספק המדומה מוצגים קובצי דוגמה.
- אין עדיין עריכת טיוטות קמפיין, ניסיון חוזר מבוקר לנמענים שנכשלו, או דוחות מתקדמים.
- הרשאות המערכת מיועדות לארגון יחיד; הפרדה בין לקוחות/ארגונים אינה ממומשת.
- יש לבדוק חיבור חי, תבניות אמיתיות וקבלת callbacks לפני שימוש לשליחה אמיתית.

## תיקון הרשאות Supabase — 23.09.2026

התראת `rls_disabled_in_public` תוקנה במסד הנתונים החי של Solina Inbox: הופעל RLS
ונשללה גישה ישירה של `anon`/`authenticated` לכל 18 טבלאות האפליקציה. Prisma ממשיך
להתחבר דרך משתמש שרת מורשה. אין להוסיף מדיניות `USING (true)` כדי להעלים הודעות INFO.
פרטי התיקון והאימות נמצאים ב־[דוח התיקון](docs/security-remediation-2026-09-23.md).
בפרויקט חדש יש להריץ את `prisma/changes/security-baseline.sql` אחרי יצירת הסכמה.

השינויים בקוד כוללים בדיקת משתמש פעיל ותפקיד עדכני בכל אימות session, הגבלת
שינויי שיחות ושיוכים להיקף הנציג והסרת שדות סיסמה מתשובות. תוכן ההודעות נטען
דרך API מאומת, עם בדיקה כל 5 שניות ואותות רענון ריקים דרך Supabase Realtime.
הלקוח אינו סומך על תוכן של שידורים ציבוריים. תיקוני קוד אלה נכנסים לתוקף לאחר פריסה.
