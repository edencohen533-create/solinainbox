# WhatsApp — בדיקת שלמות, תיקונים ו־QA, 23.09.2026

**מסקנת מוכנות: לא מאושר עדיין כמערכת WhatsApp עסקית מלאה לפי המפרט.** הושלמה בדיקת המימוש ונוספו תיקוני בטיחות ויכולות שימושיות; נשארו פערי מוצר וארכיטקטורה משמעותיים. אין חיבור Meta פעיל בפרודקשן, ולכן מסלול קמפיין ומסלול דו־כיווני **לא אומתו מול ספק חי**. לא נשלחו הודעות ללקוחות במסגרת QA.

[מטריצת 199 דרישות](qa/whatsapp-requirements-matrix.md) · [CSV לסינון ומעקב](qa/whatsapp-requirements-matrix.csv). הסטטוסים מפרידים בין מימוש חלקי, חסר, חסום ומומש עם ראיות. בדיקה מדומה אינה בדיקה חיה.

## הארכיטקטורה שנמצאה

Next.js 16 / React → NextAuth והרשאות API → שירותי שרת → Prisma / Supabase Postgres → Provider Registry → Meta Cloud API או Mock. הודעות נכנסות עוברות אימות HMAC, נרמול איש קשר, שמירה, אוטומציות והודעת invalidation ללא תוכן לקוח. הדפדפן טוען נתונים דרך API מורשה. קמפיינים נשמרים כ־Campaign + CampaignRecipient ומעובדים ב־cron במנות. אין צורך בלשונית פתוחה.

החיבור הוא **Meta WhatsApp Cloud API הרשמי, ישירות דרך Graph**, לא חיבור WhatsApp Web/QR בלתי רשמי ולא BSP. החיבור הקיים מקבל Token / Phone Number ID / WABA / App Secret; אין Embedded Signup. Registry בוחר חיבור פעיל יחיד. אין Organization/Tenant, אין מספרים מרובים, ואין אינטגרציית CRM חיצונית/רכישות/חייגן. הרשאות נציגים אינן הפרדה בין עסקים. פריסה זו מיועדת לעסק יחיד בלבד עד להשלמת ארכיטקטורה מתאימה.

## אימות מול מקורות רשמיים

מקורות נבדקו ב־23.09.2026:

- [דף התמחור הרשמי](https://whatsappbusiness.com/products/platform-pricing/): הדף הציבורי שנגיש בבדיקה מציג חיוב לפי הודעות שנמסרו, מדינה וקטגוריה, וחריגי תמחור. **לא נקבע מחיר מספרי ולא הובטח שהשירות יישאר חינם.** תעריף תקף לחשבון, מטבע, נפח ומועד עתידי לא אומת. אין במוצר מחשבון עלות שמבוסס על נתונים היסטוריים.
- [תיעוד התמחור הטכני](https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/) ו[תמחור הודעות שירות](https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/non-template-messages/): כלי הגלישה קיבל 429 / חוסר גישה. [Overview](https://developers.facebook.com/documentation/business-messaging/whatsapp/overview) דרש התחברות. לכן מגבלות throughput, שינויים עתידיים בתמחור, איכות, מכסת החשבון ותוקף גרסת API מסומנים **לא מאומתים**, ולא הועתקו מספרים ממקורות צד שלישי.
- [אוסף ה־API הרשמי של Meta ב־Postman](https://www.postman.com/meta/whatsapp-business-platform/documentation/wlk6lh4/whatsapp-cloud-api) משמש קישור למבני API. תמיכת media/templates במימוש נבדקה עם Graph mocks; אין להסיק מכך שכל יכולת Meta מומשה.
- [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security): RLS נדרש לטבלאות public. השרת משתמש ב־Prisma; גישת browser ישירה חסומה. [Changelog](https://supabase.com/changelog) שנקרא כלל שינוי שם Replication→Pipelines מ־21.09.2026 ללא שינוי API.

ברירת המחדל בקוד נשארה Graph `v21.0`; לא בוצע שדרוג עיוור. לפני חיבור חי יש לאמת גרסה נתמכת בתיעוד הנגיש לחשבון ולבצע contract tests. מגבלת 20 נמענים להפעלת worker ומגבלת דיוור אחת לנמען ב־24 שעות הן **מדיניות מקומית של היישום**, לא מכסת Meta ולא הבטחת תפוקה.

## מה תוקן והושלם

1. **קמפיין מקובע לחיבור ולתבנית**: fingerprint בזמן יצירת טיוטה, בדיקה ב־preflight וב־worker. החלפת ספק/מספר/credentials או שינוי תבנית מקומית עוצרים את הקמפיין. רשימות מוקפאות ביצירת הטיוטה; הסכמה וחסימה נבדקות שוב בשליחה. טיוטה ישנה ללא snapshot מחייבת יצירה מחדש.
2. **סיכום לפני הפעלה**: מספר queued וזכאים, סיבות החרגה, שולח, זמן ואזור זמן דפדפן, עד שלוש דוגמאות. השרת מבצע preflight מחדש בעת start/resume. אין הערכת עלות מומצאת.
3. **אי־ודאות ואידמפוטנטיות**: Message.ACCEPTED נפרד מ־SENT; timeout נשמר UNKNOWN. מזהה בקשה ייחודי של המלחין נבדק במסד; אין שליחה חוזרת של UNKNOWN. נעילת שליחה מבוזרת ל־120 שניות מונעת בקשות מקבילות בשיחה. אין הבטחת exactly-once אצל Meta.
4. **הסכמה ושירות**: opt-out שיווקי נפרד מחסימה מלאה. מקור/תאריך/היקף/אסמכתה נשמרים לשינויים חדשים; אסמכתאות ישנות אינן מומצאות. הורחבו פקודות ההסרה. שירות בחלון פעיל מותר אחרי הסרה שיווקית; כל דיוור דורש OPTED_IN. בדיקה נוספת מבוצעת לאחר הכנת ההודעה ולפני dispatch.
5. **תדירות שיווקית משותפת**: עד ניסיון דיוור אחד לנמען ב־24 שעות באמצעות עדכון אטומי, גם בין אוטומציות וקמפיינים. המדיניות שמרנית: אין שחרור אוטומטי של התקציב לאחר timeout או כשל; לא מדובר במכסת Meta.
6. **ניתוק/הרשאות**: קודי ספק מוכרים לחוסר הרשאה/חסימה חוסמים שליחה נוספת ומציגים צורך בחיבור מחדש. בדיקות חיבור שומרות מועד ושגיאה. callbacks נשארים נגישים לאימות גם כשהשליחה חסומה. מעבר לדמו אינו הופך שיחה אמיתית לשליחה מדומה מוצלחת.
7. **CSV**: עד 10,000 שורות, מיפוי עמודות, דוגמאות, ספירת כפולים ודוח שגיאות. שגיאה מונעת commit; הרשאה לבדיקה/ייבוא היא מנהל/אדמין. ייבוא אינו מעדכן הסכמה של איש קשר קיים.
8. **טיוטות שיחה**: API מורשה לפי משתמש ושיחה משתמש ב־ConversationDraft הקיים. נשמר טקסט לאחר debounce. מדיה ומשתני תבנית עדיין אינם נשמרים, וניווט לפני debounce יכול לאבד את ההקשה האחרונה.
9. **אוטומציות**: מענה אוטומטי נעצר כאשר נציג משויך; משתמש מערכת נבחר מחדש מבין אדמינים פעילים. פעולה שיווקית עוברת את אותן הגנות שליחה ותדירות. אין בוט AI חדש או workflow engine מקביל.
10. **מדדים אמינים**: הודעות FAILED/UNKNOWN אינן נחשבות מענה ראשון. חישוב זמן טיפול מתוך updatedAt הוסר: בלי אירוע סגירה אמין, מוצג שאין מדד. הוגדרו חלון, מכנה ואזור זמן לדוח הקיים.
11. **ברירת מחדל לתבנית** שונתה מ־APPROVED ל־DRAFT. שורות קיימות נשמרו, ללא המצאת החלטה חדשה של Meta.

## פערים ותלויות להפעלה מלאה

- **P0 — tenants**: אין גבול עסק במסד/סשן/שאילתות. נדרשים ארגון, membership, מספרי שולח, keys ייחודיים לפי ארגון ו־FKs שמונעים קשר בין ארגונים. הוספת tenantId בלי סגירת כל נתיבי הגישה אינה פתרון. עד אז אין לצרף עסק שני לאותה פריסה.
- **P0 — Meta חי**: החלפת סיסמאות דמו או השבתת משתמשי דמו, הרשאות מספר ו־WABA, token, app secret, verify token, subscribed_apps, בדיקת הודעה נכנסת ו־statuses ממכשיר מאושר. אימות read-only אינו מוכיח יכולת שליחה או מסירה.
- **P0 — תפעול יציב בהיקף**: חסרים retry/backoff סלקטיביים, durable webhook/outbox, reconciliation של callback שמגיע לפני שמירת providerMessageId, fair scheduling, ומצב בדיקה/גרסאות לאוטומציות. UNKNOWN אינו חוזר אוטומטית לתור.
- **P1 — מוצר**: מספרים מרובים, segment builder AND/OR והחרגות, מיזוג אנשי קשר, ייצוא, media/buttons בתבניות, test-send allowlist, עימוד היסטוריית שיחה, טיוטות מדיה, תנאי שעות שליחה ושכפול קמפיין.
- **CRM חיצוני**: נדרש שם שירות/תיעוד API ומיפוי אנשי קשר, סטטוסים, רכישות, הזמנות ומשימות. אין כרגע מקור אמיתי למכירות/הכנסות/קליקים, ולכן אין הצגת ערכים כאלה.
- **החלטות עסקיות**: מדיניות retention, הרשאות export, שעות עבודה, מטרת כל אוטומציה, frequency cap ו־CRM source of truth. המדיניות השמרנית הקיימת מפורטת לעיל, ללא הדמיה לא מסומנת.

## הגדרות הפעלה

אותן הגדרות בסיס קיימות: DATABASE_URL/DIRECT_URL, AUTH_SECRET ו־URL תקין, מפתחות Supabase שרת בלבד, CRON_SECRET ו־Vercel cron. אין להפעיל cron מול סביבת QA עם Meta אמיתי. לחשבון נדרשים מזהי Meta והרשאות שנבדקו בהגדרות. יש לבדוק cron של קמפיינים ודיליי אוטומציות בתוכנית Vercel המתאימה; אין להניח שקצב minute נתמך בכל תוכנית חינמית.

אין צורך להמציא עלויות או להחליף ספק. יש להשלים את הפערים על השירותים והמסד הקיימים, ולתת אישור מוכנות רק אחרי בדיקות קבלה חיות עם מספרי בדיקה מאושרים.
